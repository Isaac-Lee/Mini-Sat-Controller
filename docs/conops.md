# MSC 운용 개념서 — ConOps v0.1

상태: **검토용 초안 · 사용자 승인 전**

작성일: 2026-09-11

이 문서는 MSC가 누구를 위해, 어떤 상황에서, 어떤 책임과 절차로 운용되는지
정의한다. 기존 설계에 명시된 방향을 바탕으로 하며, 아래 운용 절차와 초기
범위는 제안이다. 구현 완료나 실제 위성 운용 적합성을 선언하지 않는다.

## 1. 서비스의 목적

**MSC는 사용자의 지구관측 의도를 실행 가능한 임무로 전환하고, 위성·지상국의
운용과 관측 데이터 처리를 조율하여, 요구가 충족되었는지 근거와 함께 전달하는
임무 운용 서비스다.**

사용자는 “대전을 촬영해줘”처럼 목표를 제시한다. MSC는 관측 영역을 해석하고,
가용한 관측 기회와 자원을 평가하며, 승인된 활동으로 계획을 만들고, 권한에
따라 실행을 진행한다. 사용자가 궤도·지상국·명령 형식을 직접 다룰 필요는 없다.

운용의 성공은 명령 전송이 아니라 **합의된 관측 요구를 충족하는 결과와 그 증거를
사용자에게 전달하는 것**으로 정의한다. 불가능하거나 결과를 확인할 수 없는
경우에도 이유, 불확실성, 가능한 다음 조치를 알려야 한다.

## 2. 운용 주체와 책임

| 주체 | 운용 책임 |
| --- | --- |
| 관측 요청자 | 대상과 목적을 제시하고, 필요한 기한·품질 조건 및 대안을 선택한다. |
| 임무 운영자 | 임무 진행과 예외를 감시하고, 정책상 승인이 필요한 활동과 재계획을 판단한다. |
| 승인권자 | 위험도에 따른 명령 실행 권한을 승인한다. 이중 승인이 필요한 경우 서로 다른 승인자가 참여한다. |
| 임무 정의 관리자 | 검증된 활동·명령 정의, 장비 능력, 제약과 권한 정책의 버전을 관리한다. |
| 플랫폼 운영자 | 서비스·저장소·메시징의 가용성과 복구를 관리한다. 인프라 관리 권한만으로 위성 명령 권한을 얻지 않는다. |
| MSC | 요청 해석, 가능성 평가, 계획, 실행 조율, 증거 수집, 결과 평가와 이력 추적을 수행한다. |
| 위성·지상국 시스템 | 명령 수신·실행, 텔레메트리 제공, 통신 세션과 데이터 수신을 수행한다. 초기 통합에서는 시뮬레이터가 담당한다. |

이는 논리적 역할 구분이다. 실제 인원 배치, 승인자 자격과 교대 체계는 미정이다.

## 3. 운용 환경과 경계

- 서비스 내부 범위: 요청 접수부터 계획·명령 통제·모니터링·데이터 수신 집계·L0/미리보기·요구 충족 평가까지.
- 외부 연동: 위성, 지상국, 궤도·시간·기상·지리 참조자료 공급자, 인증 체계.
- 초기 검증 환경: 독립 백엔드 프로세스와 영속 저장소에 위성·지상국 시뮬레이터를 연결한다.
- 실장비 전환 조건: 장비 프로토콜, 수치 모델 정확도, 명령 권한·키 관리, 장비별 데이터 형식과 운용 절차를 별도로 검증한다.
- 기본 운용 전제: 통신 기회는 제한될 수 있고, 관측과 수신 사이에는 지연이 있으며, 데이터와 텔레메트리가 일부만 도착할 수 있다.

상용 분석 상품, 과금·계약, 임무 간 사업 우선순위는 이 초안에서 정의하지 않는다.
관측 위성 수와 센서 종류 역시 아직 확정하지 않는다.

## 4. 대표 정상 운용 시나리오

예시 입력: “대전을 촬영해줘.” 아래는 목표 운용 흐름이며 현재 동작의 설명이 아니다.

| 단계 | MSC와 운용자의 행동 | 사용자에게 제공하는 정보 / 다음 단계 조건 |
| --- | --- | --- |
| 1. 의도 해석 | 지명을 관측 영역으로 해석하고 적용할 기본 관측 조건을 제시한다. 모호한 대상이나 필수 조건만 추가로 확인한다. | 해석된 지도 영역, 조건과 기본값. 대상이 확정되어야 요청을 접수한다. |
| 2. 요청 접수 | 요청 ID·개정 번호·기한·우선순위·완료 조건을 기록한다. | 접수 사실과 평가 중 상태. 접수는 촬영 보장이 아니다. |
| 3. 가능성 평가 | 버전이 고정된 궤도·기상·위성 상태·장비·지상국 자료로 관측 기회와 제약을 평가한다. | 후보 시간, 예상 범위, 불확실성. 불가능하면 이유와 조건 변경안을 제시한다. |
| 4. 계획 수립 | 승인된 활동으로 촬영·통신 등 필요한 활동을 구성하고 자원 충돌과 전체 시간축의 자원 잔량을 검증한다. | 잠정 계획과 확정 계획을 구분한다. 계획 변경은 새 버전으로 남긴다. |
| 5. 실행 준비·승인 | 지상국 예약과 실행 조건을 확인하고, 계획에서 명령 묶음을 생성해 권한·안전·시간 조건을 검사한다. | 필요한 승인과 지연 이유. 계획 확정만으로 명령 전송을 허용하지 않는다. |
| 6. 업링크·촬영 확인 | 허가된 명령을 전송하고, 수신·탑재·실행에 대한 증거를 따로 추적한다. | 전송됨, 실행 추정, 실행 확인, 실패, 확인 불가를 구분한다. |
| 7. 다운링크·데이터 처리 | 수신 구간과 누락을 집계하고 원본 추적이 가능한 L0와 미리보기를 생성한다. | 수신 완전성, 데이터 품질과 처리 상태. 촬영 확인과 수신 완료는 별개다. |
| 8. 요구 평가·전달 | 요청에 기록된 영역·기한·품질 조건과 결과를 비교한다. | 결과 접근 경로, 충족 여부와 근거. 미충족이면 재관측 또는 종료 판단으로 이어진다. |

구체적인 센서 조건, 구름 허용치, 해상도, 영역 커버리지와 전달 기한의 기본값은
미정이다. 시스템이 임의로 값을 정해 사용자의 요구로 기록하지 않는다.

## 5. 자동화와 권한

기존 설계의 AUTO / ASSISTED / ADVANCED는 **상호작용 선호**이며 실행 권한이 아니다.
사용 경험은 다음과 같이 제안한다.

| 상호작용 방식 | 사용자 경험 |
| --- | --- |
| AUTO | 목표 중심으로 요청하며 정책이 허용하는 작업은 자동 진행한다. 필수 결정과 예외를 알린다. |
| ASSISTED | 후보 계획과 대안의 설명을 보고 사용자가 선택하는 단계를 추가한다. |
| ADVANCED | 상세 관측 조건과 계획 근거를 조회·조정한다. 명령 권한은 별도 정책을 따른다. |

실행 권한은 활동 종류, 임무 단계, 위성 모드와 위험도에 따라 자동 허용·정책 승인·
사람 승인·이중 승인·자동 금지로 판정한다. 누가 어떤 활동을 승인할지는 추가 정의한다.
승인된 활동 정의 밖의 명령을 즉석에서 만들어 실행하지 않는다.

안전 모드 또는 중대한 이상으로 동결되면 새로운 자동 명령 출고를 멈춘다.
이미 탑재된 명령의 중단 여부는 별도 확인과 승인된 절차가 필요하다.
안전 모드 해제가 곧 자동 실행 재개를 의미하지는 않는다.

## 6. 비정상·변경 운용

| 상황 | 제안하는 운용 대응 |
| --- | --- |
| 기상·궤도·장비 제약으로 관측 불가 | 실패 이유를 설명하고 다른 시간·영역·조건을 제안한다. 사용자 요구 조건은 동의 없이 완화하지 않는다. |
| 계획 입력이 오래되거나 자원 검증이 미완료 | 실행 준비 완료로 취급하지 않는다. 자료 갱신과 재검증 후 새 계획을 발행한다. |
| 지상국 접촉 실패 | 전송 여부와 실제 탑재 상태를 확인하고 다음 접촉과 기한을 재평가한다. |
| 전송 후 응답 유실 | 결과를 UNKNOWN으로 유지한다. 명령 ID와 탑재 상태를 대조하기 전 무조건 재전송하지 않는다. |
| 위성 안전 모드·중대한 이상 | 신규 자동 출고를 동결하고 운영자에게 알린다. 승인된 비상 절차로 판단한다. |
| 일부 데이터 누락·품질 미달 | 확보된 결과와 부족한 부분을 표시한다. 추가 수신·재처리·재관측 가능성을 평가한다. |
| 요청 변경·취소 | 새 요청 개정과 영향 평가를 남긴다. 이미 동결·탑재·실행된 활동의 취소 가능성을 확인한 뒤 결과를 통지한다. |
| 서비스 재시작·중복 이벤트 | 영속 이력에서 복구하고 중복 효과를 억제한다. 실행 결과가 불명확한 활동은 증거 대조를 거친다. |

재시도 횟수, 에스컬레이션 시간, 재관측 예산, 취소 가능 시점과 동결 구간 내
계획 교체 규칙은 아직 정하지 않았다.

## 7. 사용자와 운영자가 보는 운용 상태

한 개의 진행률로 모든 상태를 표현하지 않는다. 다음 정보를 함께 제공한다.

- 요청: 접수 여부, 현재 조건과 개정, 기한, 충족 여부.
- 계획: 잠정/확정, 적용 계획 버전, 예정 활동과 재계획 이유.
- 실행: 승인·전송·탑재·실행 증거와 확인 불가 상태.
- 데이터: 수신 구간, 누락, 처리 결과, 품질과 완료 조건 평가.
- 신뢰도: 관측 시각, 수신 시각, 자료의 최신성, 추정과 확인의 구분.

지도에는 요청 영역, 위성 위치·예측 경로, 예상 촬영 범위와 임무 시간축을 표시한다.
UTC를 기본으로 표시하고 사용자 현지 시간을 함께 제공한다. 예상 시각과 범위는
확정된 결과처럼 보이지 않게 한다. 사용자용 요약에서 각 판단의 상세 근거로
이동할 수 있도록 제안한다.

## 8. 초기 운용 실증 범위와 성공 기준 — 제안

첫 실증은 **시뮬레이션 위성 1기·센서 1종·지상국 1개**에서 단일 관측 요청을
끝까지 처리하는 것으로 제한한다. 이는 장기 서비스 규모나 실제 장비 선정이 아니다.

1. 요청 → 계획 → 승인 → 명령 → 실행 확인 → 수신 → L0/미리보기 → 요구 충족 평가가 독립 프로세스 사이에서 이어진다.
2. 결과에서 요청 개정, 계획 버전, 활동 정의, 입력 자료, 명령과 수신 증거를 추적할 수 있다.
3. 촬영 확인만으로 완료하지 않으며, 명시된 관측 조건과 전달 결과로 완료를 판정한다.
4. 접촉 실패, 응답 유실, 데이터 누락, 안전 모드에서 각각 보류·불확실성·미충족·동결이 올바르게 나타난다.
5. 프로세스 재시작, 메시지 중복, 동시 계획 변경이 이력 손실이나 중복 명령 실행으로 이어지지 않는다.
6. 시뮬레이션·리플레이·섀도 계획은 실장비 명령 경로와 격리한다. 섀도 계획은 운영 계획을 변경하지 않는다.

처리 지연, 관측 성공률, 서비스 가용성과 복구 시간의 수치 목표는 운용 조건과
실증 측정 후 정한다. 시뮬레이터 합격은 실제 임무 적합성 검증을 대체하지 않는다.

## 9. 현재 구현과의 차이

2026-09-11 저장소의 검증 문서에는 임무 정의와 Flight Dynamics 독립 서비스,
영속 저장·메시징·객체 저장 연동, 제한된 궤도 및 기하학적 접근 기회 계산의
검증이 기록되어 있다. 명령 출고 정책의 도메인 테스트도 기록되어 있다.

전체 요청-결과 운용, 실전 계획·자원 검증, 명령 전송 서비스, 시뮬레이터 실행
대조, 데이터 제품·요구 충족 평가와 운영 UI는 완료되지 않았다. 이 문서 작성 시
테스트를 재실행하지 않았으며, 위 설명은 저장소의 기존 검증 기록을 기준으로 한다.

| 순서 | 결정 | 이 초안의 제안 |
| --- | --- | --- |
| 1 | 주 사용자와 사용 맥락 | 비전문 요청자가 목표를 입력하고, 별도 임무 운영자가 예외와 승인을 맡는다. |
| 2 | 첫 운용 범위 | 위성 1기·센서 1종·지상국 1개의 시뮬레이션에서 전체 흐름을 실증한다. |
| 3 | 완료 조건과 자동화 권한 | 요청별 영역·품질·기한·산출물을 명시하고, 활동별 승인 정책을 별도로 정한다. |
