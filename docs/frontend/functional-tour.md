# FE 기능 확인판 — 사용 안내와 완료 근거

2026-09-12. 사용자가 지정한 범위는 기존 아키텍처를 유지하면서 전체 기능과 서비스의
역할·연결을 파악할 수 있는 FE입니다. 운영 기능 전체를 처음부터 완성하는 범위는 아닙니다.
새 시뮬레이션의 모든 명령을 FE에서 생성·승인·실행하는 운영 콘솔 완성으로 표시하지 않습니다.

## 시작

기존 로컬 백엔드와 포워딩이 실행 중일 때:

```sh
npm --prefix msc-ops-console run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

http://127.0.0.1:5173/ 을 엽니다. 인증은 기존 개발 프록시가 `.local/msa.env`를 읽어
대리하며 브라우저에 비밀번호를 보내지 않습니다. 운영용 로그인은 구현 범위 밖입니다.
포워딩이 없으면 `docs/backend/local-runtime.md`를 따릅니다. DB/볼륨 초기화는 필요 없습니다.

## 둘러보는 순서

1. **전체 서비스**: 12개 서비스가 받는 것과 만드는 것, 화면 간 이동 순서를 확인합니다.
   이 설명은 서비스 가동 상태 표시가 아닙니다.
2. **Mission Map**: SPACEEYE-T1 공개 궤도와 출처·epoch를 확인합니다. 궤도 수집·가져오기·
   위치 예측과 재생, 보존 GP에서 파생한 TLE 다운로드를 제공합니다. 실제 위성 텔레메트리와
   합성 촬영 위성은 구별됩니다. 지도 AOI는 요청 영역이며 센서 투영 오버레이는 미연결입니다.
3. **요청 → 완료된 예시 열기**: 목록의 FULFILLED 요청 중 첫 항목을 실제로 선택합니다.
   하드코딩한 요청 ID나 mock 데이터가 아닙니다. 예시가 없으면 버튼은 비활성입니다.
   요청 제출·취소 및 원본 조회는 기존 실제 API를 사용합니다.
4. **임무 흐름**: 최신 입력 시도의 계획/후보를 선택하고 자원·조명·샘플 카메라 평가를 확인합니다.
   아래 실행 카드는 완료 결과에 고정된 실제 명령을 별도로 따라갑니다. 각 일정 카드가
   실제 사용한 요청·계획·후보 ID를 표시하므로 최신 후보와 혼동하지 않습니다.
5. **촬영/다운링크 카드**: 방출 당시 일정 버전·검토자·안전 검사, 전달 당시 원장,
   후속 실행 확인을 구분합니다. 전달 기록의 PENDING은 현재 미실행을 뜻하지 않습니다.
6. **수신·제품 출처**: 지상국 예약 ID/당시 상태, 수신 계획, 예상·실제 바이트 수와 완전성을
   봅니다. 각 카드의 서버 근거를 펼치면 보존된 세부 카탈로그·검사·해시를 볼 수 있습니다.
7. **이 위성 모니터링 / 이 위성 안전 상태**: 계획에 있는 합성 위성 ID로 해당 화면을 엽니다.
   오래된 텔레메트리는 실제 STALE로 표시하며 정상으로 바꾸지 않습니다. 안전 조회는 저장된
   latch이며, 수동 안전 검사는 새로운 동결을 발생시킬 수 있는 별도 동작입니다.
8. **제품**: 요청에 귀속된 합성 완료 근거와 원본/진단 PNG를 조회·다운로드합니다.
   SIMULATION V1 완료는 실제 영상 품질·연속 촬영·물리 커버리지 검증이 아닙니다.
9. **타임라인**: 요청 생명주기·입력 시도를 확인하고 공개 궤도의 AOI 중심점 접근 기회를
   계산할 수 있습니다. 이 점 접근 기회는 AOI 전체 커버리지나 확정 일정이 아닙니다.

데모 모드는 실제 근거 조회를 중단하고 예시/설명만 표시합니다. API 실패를 데모 데이터로
바꾸지 않습니다. 새 시나리오 생성부터 일정·명령·제품 등록까지의 기존 BE 실행 안내는
`docs/backend/v1-review.md`와 `python3 scripts/verify-v1.py`에 있습니다. 그 스크립트는
새 합성 데이터와 저장 결과를 만드는 동작이며 이 FE 개발 중 재실행하지 않았습니다.

## 요구사항별 검증

| 요구사항 | 구현과 근거 |
|---|---|
| 기존 아키텍처 보존 | BE/DB/배포 변경 없이 React 화면 및 기존 Vite 프록시만 확장. 새 패키지 의존성 없음 |
| 서비스 전체 이해 | OverviewPanel의 12개 역할·입출력 카드와 각 화면 이동, 데스크톱/390px 브라우저 확인 |
| 요청에서 결과까지 연결 | 실제 요청 `0e1eed4c-e2a4-4e6c-9909-5066279f846e`를 목록에서 선택, 후보·확정 일정의 ID·실행·수신·제품을 브라우저에서 조회 |
| 출처/관측/예측/시뮬레이션 구분 | 공개 궤도 대상 라벨, SIMULATION 환경, 서버 완료 근거, 독립적인 계획/실행 출처, TAI 원본/UTC 근사 |
| 실 API와 실패 구분 | 계획/명령/Product GET 200 및 개별 오류 상태, 404/503·잘못된 요청·늦은 응답·데모 전환 단위 테스트 |
| 수신 결과 확인 | 이전 제품 slice의 실제 원본 1,000,000 bytes/PNG 651 bytes 해시 대조; 현재 흐름 카드에서 COMPLETE·지상국 CONFIRMED 조회 |
| 카메라/TLE | 카메라 v1 GET 200, 샘플 10개·범위 SAMPLED_FOOTPRINT_NOT_CONTINUOUS_EXPOSURE; TLE GET 200·140 bytes |
| 선택 위성 연결 | 임무 흐름에서 모니터링 이동, 실제 합성 위성 ID·SIMULATION·STALE·NOMINAL·배터리/저장소/추진제 표시 확인 |
| 기본 품질 | 빌드 통과, lint 경고 없음, 37개 테스트/9파일 통과. 독립 Codex 리뷰 및 후속 카메라/TLE 리뷰에 미해결 발견 없음 |

카메라 추가 후 최초 라이브 확인은 502로 실패했고 같은 endpoint의 후속 조회는 200이었습니다.
원인은 단정하지 않습니다. 일시적 서비스/프록시 오류는 실패 메시지로 표시하며 새로고침으로 재시도합니다.

## 한계와 후속 작업

- FE에서 새 V1 시나리오 생성·후보 확정·명령 준비/방출·완료 등록을 모두 조작하는 기능은 미구현입니다.
  현재 제공하는 전체 흐름은 저장된 실제 결과를 탐색하는 기능 확인판입니다.
- 요청 수정·지명 자동완성·안전 이력 타임라인, 센서 footprint 지도 오버레이는 후속 UI입니다.
- 모든 기존 화면의 변경 동작/오류/키보드 경로를 이번 작업에서 전수 라이브 검증하지 않았습니다.
  신규 연결은 읽기 위주이며 전체 운영 FE E2E 완료로 해석하지 않습니다.
- 기존 서버의 관측 자료는 오래되어 STALE이 될 수 있습니다. 새로운 관측 주입으로 몰래 보정하지 않습니다.
- 새 컴퓨터 실행 절차는 [BE·FE 통합 안내](../backend/cross-machine-quickstart.md)를 따르세요.
  위 검증 표는 2026-09-12 당시 기록이며 새 컴퓨터에서의 실행 검증을 뜻하지 않습니다.

## 실행 비용

새 서비스·K8s 배포나 자원 요청 변경은 없습니다. 임무 흐름을 열거나 새로고침하면 요청별
계획·명령·제품 근거를 읽고, 선택한 계획의 자원·카메라·조명 근거를 읽습니다. 자동 폴링은 없습니다.
다수 계획이 있는 요청에서는 계획 수만큼 읽기 요청이 늘어나며 운영 규모 부하 검증은 미수행입니다.
